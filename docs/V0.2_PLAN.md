# V0.2 implementation plan

V0.2 builds a practical two-deck workflow on the runtime-accepted V0.1 stage.
The server continues to own one stage revision and one PA output. Each snapshot now
also carries Deck A, Deck B, the queue, the active deck, and normalized now-playing
data. Clients derive finite-track position from server time and create their own
provider instances.

Implemented scope:

- config-driven addon tracks and streams with normalized cached lookup;
- Deck A/B load, play, pause, resume, stop, seek, and backend capability checks;
- DJ-local native cue with teardown on close or operator loss;
- server-authoritative queue add/remove/reorder/clear/load-next;
- deterministic CUT output switching;
- searchable, source-filtered library and two-deck AE3-sized dashboard;
- one optional source-pack PBO containing two original development signals;
- unchanged V0.1 authorization, revision, JIP, AE3, and Carpinchos boundaries.

The static, engine, dedicated, packaging, and 30-item interactive gates are complete.
The accepted evidence is recorded in `V0.2_VALIDATION.md`; human audio, visual, and
multiplayer results came from the operator rather than log inference.

Beat analysis, waveforms, pitch/key lock, EQ, filters, scratching, DSP crossfades,
lighting, LED walls, external dashboards, and Discord integrations remain outside
V0.2.
